# v0.1.1 protocol remediation matrix

This matrix freezes the protocol findings accepted for the v0.1.1 candidate. The
implementation must fail closed: every public request option is encoded
exactly, rejected as unsupported, or rejected as an invalid request.

| ID | Finding | Verdict | Current evidence | Required behavior | Test |

| R02 | Messages maps service tier to `speed` | valid | `encodeMessagesRequest` writes `speed` | separate service tier and generation speed | T002 |
| R03 | Anthropic enabled thinking lacks a budget | valid | thinking encoder emits only `type` | reject `Enabled`; validate Budget and Adaptive | T003 |

## Public API impact

The following are intentional source and ABI breaks for the unreleased v0.1.1
candidate. No compatibility aliases are provided:

- `encodeRequest` returns an encoded request plan instead of a string.
- service tier, generation speed, cache, structured output, and capabilities
  become typed dialect rules.
- validation is always strict; `LlmWireValidationPolicy` is removed.
- tool arguments use a single canonical JSON value.
- display reasoning and provider-native replay become different block types.
- usage counters distinguish missing values from zero.

The migration guide, public API inventory, error-code inventory, examples, and
external consumer must change atomically with the corresponding implementation.
